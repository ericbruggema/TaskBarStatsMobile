# TaskBarStatsMobile — projectinstructies voor Claude

Android-companion van de Windows-monitor TaskbarStats (aparte repo: github.com/ericbruggema/TaskbarStats). De gebruiker praat Nederlands; commentaar in de code is Nederlands; UI-teksten staan in `res/values` (en), `values-nl`, `values-de`. Openbaar op GitHub (MIT): geen persoonlijke gegevens, geen echte screenshots met privé-inhoud. **Nooit committen of pushen zonder dat de gebruiker daar expliciet om vraagt.** Demo-video's en gifs altijd in het Engels. Na elke zichtbare UI-wijziging de screenshots in `docs/screenshots/` opnieuw maken (emulator `tsphone`) en tonen.

## De app

Aparte Kotlin/Jetpack Compose-app (geen port van de WinForms-code); eigen README met alles: `README.md`. Kort:
- Bouwen: JDK 17 + Android SDK (platform 35) nodig; `./gradlew assembleDebug` (`local.properties` met `sdk.dir` is git-ignored). Testen op een emulator (`system-images;android-35;google_apis;x86_64`, WHPX); `adb`-schermafbeeldingen zijn van de emulator met verzonnen verkeer, dus geen privacyprobleem.
- Geen accu (Android toont die al), geen GPU/FPS. CPU% alleen via **Shizuku** (`ShizukuCpu.kt`, `IStatsService.aidl`, `UserService` leest `/proc/stat`); `dumpsys cpuinfo` met `DUMP` werkt NIET (service onzichtbaar voor gewone apps, SELinux).
- `Sampler` (1 s, eigen thread) levert een onveranderlijke `Snapshot`; `StatsRenderer` tekent widget/melding naar een `Bitmap` (zelfde idee als `WidgetRenderer`); `StatusBarOverlay` = niet-aanraakbaar overlay-venster ter hoogte van de statusbalk (verbergt zichzelf als de statusbalk weg is, krimpt/laat cellen weg op smalle schermen); `Themes.kt` = dezelfde 14 kleurenthema's als Windows + import van een Windows-themabestand (alleen de vier kleuren).
- Alle percentages en balken worden op 0-100 begrensd (`Snapshot.memPercent`, enz.).
- Valkuilen: Kotlin-regex in een gewone string heeft een dubbele backslash nodig (`Regex("\\s+")`; een enkele `"\s"` geeft een compilefout); Git Bash vertaalt `/sdcard/...`-paden in `adb` (zet `MSYS_NO_PATHCONV=1`); `gradlew` moet vanuit de hoofdmap draaien (vanuit een submap faalt hij stil als je de uitvoer filtert); een tweede `am start` op de draaiende `singleTop`-activity geeft alleen een nieuwe intent (eerst `force-stop` voor een andere tab).
- Ook aanwezig: `Tiles.kt` (tegels aan/uit + volgorde, dashboard en cockpit), `WidgetOptions.kt` + `WidgetConfigActivity.kt` (cellen en doorzichtigheid per widget-id; de launcher opent het instelscherm bij vastgezette widgets niet, daarom een knop in de app), `StatsTileService.kt` (Quick Settings-tegel; testen met `adb shell cmd statusbar add-tile <pkg>/<pkg>.StatsTileService`).
- Release: `build-release.bat` -> ondertekende, met R8 verkleinde APK (~1 MB) + AAB. `keystore.properties` en `taskbarstats-release.jks` staan naast `gradlew`, zijn git-ignored en zijn lokaal gegenereerd met `keytool`; maak er een back-up van (een andere sleutel kan een geïnstalleerde versie niet bijwerken). `proguard-rules.pro` houdt de Shizuku-`UserService` en de AIDL-stubs.
- Test-tips: een lang inline Python-script in Bash geeft soms `unexpected EOF`; schrijf het als bestand in de scratchpad en voer dat uit. Vaste schermpunten voor `adb shell input tap` (1080x2400): lees ze af uit een schermafbeelding (x1,2 ten opzichte van de getoonde coördinaten).
- Meldingsactie *Stop* (`MonitorService.ACTION_STOP`), CI `.github/workflows/android.yml` (debug-build + lint; nog niet op GitHub gedraaid), conceptvermelding `PLAY-STORE.md`. Lint: `MissingTranslation` staat uit (nl/de woorden gelijk aan Engels). Shell na compaction mist `JAVA_HOME` (jdk-17 onder `C:\Program Files\Microsoft`) en `adb` in PATH.
- **Naam en pakket**: de app heet `TaskBarStatsMobile`, `applicationId` = `com.ericbruggema.taskbarstatsmobile`; `namespace` en de Kotlin-pakketnaam blijven `com.ericbruggema.taskbarstats` (dus `am start -n com.ericbruggema.taskbarstatsmobile/com.ericbruggema.taskbarstats.MainActivity`; `run-as`/adb-commando's gebruiken de nieuwe applicationId). De Windows-app blijft `TaskbarStats`.
- Procesdetails en cache (`Details.kt`, `IStatsService.processDetails/runAction`): tik op een proces -> dialoog met opdrachtregel, ouder, gebruiker, leeftijd, `dumpsys activity processes` (wat het proces draaiende houdt, componenten) en acties (app openen, app-info, `am force-stop`, `kill -9`, opdrachtregel kopiëren); opslag toont app/gegevens/cache, `pm trim-caches 999G` wist de caches van alle apps (apps in gebruik houden soms wat), per app alleen via de app-info-pagina. `pm clear --cache-only` hing op de emulator.
- Tabs Apps/History/Alerts/Permissions (`Tabs2.kt`, `AppData.kt`, `Alerts.kt`): per-app verkeer/opslag/schermtijd via Usage Access (`NetworkStatsManager`, `StorageStatsManager`, `UsageStatsManager`), autostart = `BOOT_COMPLETED`-ontvangers (vraagt `QUERY_ALL_PACKAGES`), proceslijst = `top` via de Shizuku-`UserService` (`IStatsService.topProcesses`), historie per minuut in geheugen. Elke speciale toestemming heeft een kaart op het tabblad Permissions met knop naar de juiste instellingenpagina; `resumeTick` leest de status opnieuw bij terugkeer. Usage Access testen op de emulator: de schakelaar op de Android-pagina aanzetten (of `adb shell appops set <pkg> GET_USAGE_STATS allow`). `stringResource` zonder argumenten verwerkt `%%` niet (toont letterlijk `%%`): gebruik een woord i.p.v. een procentteken in zulke teksten.
- Statusbalk-onderdelen (`StatusItems.kt`, `Setup.kt`, `MonitorService.updateNotifications`): eerste-start-scherm (`setup_done`) kiest onderdelen (`items`: down,up,mem,cpu,disk,ping,temp) en waar (`icons` = één melding per onderdeel met een zelf getekend tekst-icoon via `Icon.createWithBitmap`, wit op transparant; `overlay` = tekststrook, schuift op voorbij de iconen bij positie links). Gebruik per melding een eigen `setGroup(...)`, anders vouwt Android ze samen tot één algemeen icoon; kanaal `icons` heeft normaal belang zonder geluid (stille kanalen tonen op sommige telefoons, zoals Samsung, geen statusbalkicoon). Het kanaal van een al geplaatste melding verander je niet door opnieuw te `notify`'en. In een Bash-aanroep met `export MSYS_NO_PATHCONV=1` vóór `gradlew.bat` verdwijnt de padomzetting van `JAVA_HOME` (zet die export pas na de gradle-aanroep).
- Demo-video's Android (`docs/videos/`, Engels): echte schermopnamen van de emulator (`adb screenrecord` + `input`, verzonnen verkeer via `nc`), gemonteerd met ffmpeg/PIL; toolkit in `tools/demo` (lees de README daar: slapend scherm = INVALID_LAYER_STACK, proceslijst alleen opnemen zonder verkeersgenerator).
- Nog niet: persistente historie, Play Store-afbeeldingen/privacybeleid, test op echte hardware.
